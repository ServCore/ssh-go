# 主题与图标用色

在「设置 → 外观」中分别选择外观模式与主题色。主题色提供蓝、绿、红、橙、紫，亮色与深色各有对应前景色；选择会立即生效并保存到本机。新用户默认紫色；已有本地或桌面偏好继续保留。

## 深色表面

深色采用带轻微紫色倾向的炭灰层次，减少蓝色底板的存在感。参考 Apifox 的颜色分工，将主操作填色、可读前景和淡底选中态分开。浅色模式保持中性表面。设计依据见 [Apifox 风格研究](APIFOX_STYLE_RESEARCH.md)。

| 用途 | 色值 |
| --- | --- |
| 工作区 / 终端背景 | `#222129` |
| 顶栏 / 状态栏 | `#1b1a22` |
| 卡片 / 会话工具栏 / 弹窗 | `#292831` |
| 抬升表面 | `#32303c` |
| 分隔线 | `#3a3846` |
| 正文 / 次级文字 | `#efedf5` / `#b9b6c7` |

主题色的浅底和边框在当前表面色上混合生成，避免更换深色底板后残留旧色调。在线状态、系统品牌标识、告警与监控指标继续使用各自的语义颜色。

## 用色规则

| 用途 | 规则 |
| --- | --- |
| 主按钮 | 饱和实色底与白色前景，亮暗模式均保留清晰力度 |
| 链接、操作图标、选中态、焦点 | 跟随主题色，深色前景独立提亮，包括上传文件、上传目录与文件夹图标 |
| 搜索、刷新列表、未选中模式与工具栏辅助按钮 | 普通态中性，hover 或选中时强调；连接 Tab 使用中性表面与主题细线 |
| 在线、成功、警告、错误、危险操作 | 保留语义色，避免红色主题下无法区分操作与错误 |
| 正常监控指标与图表数据系列 | 保留指标颜色，避免切换主题改变数据含义 |
| 关闭、更多、禁用控件 | 继承所在控件的颜色，保持清晰的层次与可用状态 |
| 终端 | 光标和选择区域跟随主题；命令输出的 ANSI 颜色保持原样 |
| 系统与品牌标识 | 使用鲜艳纯色底块配白色标识，亮色和深色保持一致；通用服务器头像底块跟随主题 |

## 开发约定

色板集中定义于 `frontend/src/lib/accent.ts`。新增界面使用 `--accent`（前景）、`--accent-soft`（浅底）、`--accent-line`（边框）、`--focus-ring`（焦点）、`--action-fill` / `--action-hover` / `--action-pressed`（实色主操作状态）和 `--on-accent`（主按钮前景）、`--accent-solid`（需要白色图标的实色底块），避免在操作控件中写死蓝色或某种主题色。

`AppIcon` 默认使用主题色。需要继承父级颜色时使用 `tone="inherit"`；辅助工具上下文按需通过 `--icon-color: currentColor` 收敛；语义、主按钮和禁用上下文通过 `--icon-color: currentColor` 统一继承。Arco 的主色阶通过 `--accent-primary-1` 至 `--accent-primary-10` 映射，因此弹窗、选择器等组件也使用同一色板。

修改色板后检查亮色与深色模式中的图标、主按钮前景、选中态、焦点及禁用态。相关回归见 `frontend/tests/ui/theme-accent.spec.ts`，同时覆盖偏好恢复、连续保存失败后恢复和终端保留。

系统图标色块集中定义在 `frontend/src/lib/hostSystem.ts`，例如 Ubuntu 橙色、Debian 玫红、CentOS 琥珀黄。避免套用操作图标的浅色前景与淡底组合，以免在深色卡片上显得灰淡。

## 控件层级

共享 `--control-compact: 28px`、`--control-height: 32px`、`--control-form: 36px` 与 `--control-radius: 6px`。首轮覆盖服务器工具栏、会话模式、右侧辅助操作与监控采集按钮；文件区等后续按空间需要逐项收敛。

连接 Tab 当前项使用中性表面、细边框和底部主题线，避免与淡底的会话模式按钮混淆。非当前 Tab 的关闭按钮在 hover 或键盘焦点进入时出现；触摸设备保持可见。服务器卡片仅轻量强调边框，详情仍由独立按钮打开，双击或 Enter 打开终端。

五种实色主按钮与白字的对比度均不低于 4.5:1（本次最低为绿色 4.65:1）；hover / pressed 进一步加深填色。在线和指标语义色、终端 ANSI 色保持独立。

## 监控的状态表达

监控正常色采用翠绿（亮色 `#159e69`，深色 `#4ce7ac`）；亮色的小字号容量数值使用同色系 `#0d875c` 保持白底清晰度；关注为琥珀色，资源紧张为红色，未知为灰色。配合状态文案与原因，避免仅靠颜色传递含义。卡片背景保持中性，CPU、内存、磁盘不增加 hover 背景。

左侧「系统负载」显示实际的一分钟平均负载、CPU 核数和小号负载状态标签，圆环显示负载 / 核心数；卡片状态只取决于负载，不受其他资源影响。底部的资源提示独立综合 CPU、内存、所有已采集磁盘分区及采样警告，直接指出具体指标或分区；磁盘提示包含挂载点、已用比例和可用容量。分区空间偏紧时，仅提示标题和图标使用琥珀色，负载正常的主卡保持中性边框和正常状态，不显示笼统的大字告警。这里表达资源压力，不代表业务服务可用性。

| 指标 | 需要关注 | 资源紧张 |
| --- | --- | --- |
| 1 分钟负载 / CPU 核数 | ≥75% | ≥100% |
| CPU 使用率 | ≥75% | ≥90% |
| 内存使用率（不含可回收缓存） | ≥80% | ≥90% |
| 磁盘使用率（包含非根分区） | ≥80% | ≥90% |

阈值集中在 `frontend/src/features/monitor/health.ts`，属于当前界面的提示规则。资源提示优先显示已知的高压力问题；缺少关键指标时说明等待哪一项采样，不对整机作正常判断。主卡的「负载正常」只描述已采集的系统负载。

暂停、窗口隐藏、连接断开、采样失败或最近快照超过 15 秒未更新时，当前资源指标转灰，显示「状态待确认」及原因，保留上次数字与历史曲线。恢复采集须等待新的成功快照。网络历史曲线继续保留上下行的系列颜色，当前速率转灰。

正常负载状态点使用轻微的呼吸动画，旁边的装饰性脉动符号表示实时采样，不承载采样数据。实际负载数字是主信息，负载状态使用小标签；卡片边框和背景保持中性，其他资源压力只影响各自的读数和具体提示。

圆环轨道使用低强度状态色，进度弧使用同色系渐变；深色模式增加小范围柔光与环内光感，保留真实进度比例。每个渐变使用独立 SVG ID，避免多会话之间串色。未知状态移除光感并转灰。关注与紧张状态不闪烁。遵守 `prefers-reduced-motion`，关闭呼吸、脉动与圆环过渡。

## 操作反馈动效

连接中的服务器状态点显示轻微扩散，重连按钮的刷新图标慢速旋转；结束尝试或切换到其他页面后停止。在线状态点保持静止。底部传输图标按上传、下载方向轻移，混合传输仅轻微明暗变化，只有排队任务时保持静止。

进度条以 240ms 过渡到实际字节比例，不模拟进度。字节到达 100% 但仍在提交时保持“正在提交”，收到完成状态才转为绿色勾选，短暂反馈后静止；底部完成提示保留 1.6 秒。启动历史、重复完成事件、后台完成及重新打开队列不播放完成动画。

有效拖拽目标以 120ms 淡入高亮，图标轻微上移；提示层不拦截鼠标，落下后立即处理传输。窗口进入后台时暂停操作动效，回到前台不重播完成反馈。系统启用“减少动态效果”时关闭这些动画及过渡，保留状态文字、颜色与图标。
