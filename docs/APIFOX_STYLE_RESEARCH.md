# Apifox 风格研究与主题调整建议

研究日期：2026-10-23。本文记录观察与建议。首轮已落实到主题颜色职责、服务器列表、连接 Tab 和会话工具栏，具体约定见 [主题与图标用色](THEMING.md)。

## 参考与证据范围

- [Apifox 官方亮色、暗色产品示例](https://apifox.com/apiskills/free-team-api-tool/)
- [官方发送请求文档](https://docs.apifox.com/send-request)
- 本地参考图：`output/references/apifox-overview.png`（亮色）、`output/references/apifox-editor-dark.png`（暗色）。

官方文章中的图像资源路径标注为 2023/2024 年；不能据此认定为当前客户端的全部样式。图片包含宣传框、发光和功能说明浮层，这些不属于工作界面的常规装饰。网页端打开超时，未实测 hover、pressed、focus、disabled。下面的状态方案与尺寸是为 ssh-go 提出的设计约定，并非 Apifox 内部设计 token。

## 观察

### 主题色承担层级，不是给所有元素统一染色

紫色集中用于主操作、当前导航、当前页签、勾选与部分链接。相同色相有实色按钮、淡底选择、文字/线条几种强度。普通文件夹、工具栏和设置图标大多为中性色；接口方法、示例类型、成功/失败标记继续保留自己的颜色。官方文档也明确以橙色标记请求与定义的不一致。

亮暗模式保留相同的用途关系，但改变背景和强调色的相对亮度。不能把所有前景、按钮填色、选择背景都绑定到一个色值，也不能仅通过全局 opacity 生成所有状态。

### 按钮通过视觉重量区分用途

亮色运行界面里，“发送”为实色紫色按钮，“暂存”“保存为用例”为低对比边框按钮；另一个暗色编辑示例中，“保存”为实色、“运行”为紫色描边、“删除”为中性描边。因此层级取决于当前任务，而不是把某个动词永远固定为主按钮。

附属操作与主操作紧邻，例如发送右侧的下拉段、暂存旁边的恢复图标。按钮的高度、基线、边框与间距一致，依靠填色区分强弱。工具图标通常不长期显示厚重底块。示例中的按钮偏紧凑，圆角克制；不把所有按钮做成胶囊。

### 深色通过相近表面分层

参考图中的主工作区为蓝紫炭灰，侧栏、输入区和弹出层略亮，分隔线低对比。它的观感不只来自紫色，而来自大面积安静表面与少量亮色的比例。我们的工作区 `#1f2033` 已接近这一方向，无需先把整页强行改成紫色或纯中性灰。

### 排版以工作区为中心

界面由连续的侧栏、工具栏、表格和内容区构成，尽量使用细线与对齐形成分组。文字通常按正文、次级说明、弱提示分层。标题与操作不依赖大留白或大量投影争取注意力。小圆角用于控件，较大圆角用于容器，不能混成一种尺寸。

## 对照当前实现

| 当前实现 | 影响 | 建议 |
| --- | --- | --- |
| `accent.ts` 中深色 `main` 同时供按钮填色和图标/链接使用 | 适合文字的浅色也进入主按钮，填色缺少稳定力度 | 分开定义实色操作底与可读前景色，分别验证亮暗对比度 |
| `AppIcon` 默认主题色 | 许多普通工具图标长期突出 | 保留用户希望的彩色上传等明确操作图标；折叠、排序、搜索等辅助图标中性，选中或交互时强调 |
| 各区域单独指定按钮高度、字号、圆角 | 26/30/32/34/36px 等缺乏清晰的用途分档 | 提取用途明确的尺寸 token，逐区域收敛，避免一次覆盖造成布局回归 |
| 连接页签、模式切换、操作按钮均采用相近淡底块 | 导航层级与动作层级容易混淆 | 连接页签表现文档式标签；终端/SFTP/监控表现模式选择；实色留给当前主动作 |
| 鲜艳系统徽标已与操作主题解耦 | 能快速识别系统 | 保留品牌色与在线状态，切换红色主题不改变 Ubuntu、Debian 或在线绿色 |

## 建议采用的规则

### 颜色职责

| 职责 | 用途 |
| --- | --- |
| `action-fill` / `action-on-fill` | 主按钮底与前景，单独确定对比度 |
| `accent-fg` | 链接、选中图标、文字按钮 |
| `selection-bg` / `selection-border` | 当前页签、当前模式、选中行 |
| `focus-ring` | 键盘焦点，不能由 hover 代替 |
| `surface` / `surface-raised` / `surface-hover` | 页面分层与普通工具按钮状态 |
| `success` / `warning` / `danger` / `brand-*` | 在线、告警、删除和系统身份，保持语义独立 |

主题色切换改变前四组中相关色相，不改变页面全部底色。红色主题下，普通主按钮与删除操作还应通过文案、图标和布局区分。

### 按钮与状态（拟定）

- 主按钮：实色，承担区域内当前最重要的提交或创建动作；同一紧凑操作组通常只突出一个。
- 次按钮：中性表面与细边框。需要额外强调的次级动作可用主题色描边。
- 工具按钮：透明或轻底，普通态克制；hover 提高表面对比，pressed 进一步加强，焦点独立可见。
- 禁用态：降低前景与边框对比，保持标签可读，移除交互反馈。
- 导航选中态：淡主题底或细下划线，依据所在层级选择一种方式，避免同时堆叠强边框、阴影和实色。
- 初始尺寸建议：紧凑工具 28px、普通工具栏 32px、表单动作 36px；按钮圆角 6px，图标 16–18px，图文间距 6px。以上为本项目建议，待真实窗口验证。

## 下一轮调整顺序

先在服务器列表和会话工具栏制作完整样例，覆盖普通、选中、hover、pressed、focus、disabled，以及亮色/深色。确认主次层级与用色比例后，再推广到 SFTP、监控、弹窗与设置。保留既有连接逻辑和用户已选主题色偏好。不能仅把蓝色替换成紫色就视为完成。
